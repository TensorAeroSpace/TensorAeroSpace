# Инкрементальное GDHP (IM-GDHP)

Реализация опирается на статью **Bo Sun и Erik-Jan van Kampen (2021)** [Intelligent adaptive optimal control using incremental model-based global dual heuristic programming subject to partial observability](https://doi.org/10.1016/j.asoc.2021.107153) и её [полный текст в репозитории авторов](https://pure.tudelft.nl/ws/portalfiles/portal/90401508/1_s2.0_S1568494621000764_main.pdf). В статье алгоритм называется **IGDHP**; имя пакета `im_gdhp` сохранено.

## Архитектура и уравнения

Актор и критик получают ошибку слежения. Для идентификации скрытой динамики используется окно **измеренных приращений ошибки и управления**. Объединение наблюдения, задания и ошибки в один вектор не заменяет историю и не гарантирует наблюдаемость. Размер `history_length` зависит от объекта и динамики задания; для идентификации нужно достаточное возбуждение.

У критика **один скалярный выход J**. Autograd вычисляет его точную производную по входу и смешанные производные по входу и весам. Независимой головы lambda нет. Слои критика не имеют смещения, поэтому `J(0)=0`. У актора есть постоянный вход 0.01 и ограниченный выход tanh. Один скрытый слой соответствует архитектуре статьи; дополнительные слои являются расширением.

Уравнения (31)–(38), (51)–(67), записанные для векторов-столбцов:

\[
e_t=y_t[\mathrm{tracking}]-r_t,\qquad
\hat e_{t+1}=e_t+\sum_{j=0}^{M-1}F_j\Delta e_{t-j}+\sum_{j=0}^{M-1}G_j\Delta u_{t-j}.
\]

\[
J(e)=w_{c2}^{T}\sigma(w_{c1}^{T}e),\qquad
\lambda(e)=\nabla_e J(e).
\]

\[
c=e^TQe+u^TRu,\quad
D=I+F_0+G_0\frac{\partial\pi}{\partial e},\quad
\lambda_{\rm target}=\nabla_e c+\gamma D^T\lambda(\hat e_{t+1}).
\]

\[
E_c=\frac{\beta}{2}(J(e_t)-c-\gamma J(\hat e_{t+1}))^2
+\frac{1-\beta}{2}\|\lambda(e_t)-\lambda_{\rm target}\|^2,
\qquad \beta=\frac{1}{1+\texttt{beta\_lambda}}.
\]

\[
E_a=\frac12 J(\hat e_{t+1})^2,\qquad
\nabla_w E_a=J(\hat e_{t+1})\frac{\partial\pi^T}{\partial w}G_0^T\lambda(\hat e_{t+1}).
\]

При ненулевом `control_R` производная текущей стоимости содержит путь через актор: `(dπ/de).T @ (2 R u)`. Единичная матрица в `D` появляется из-за прибавления текущей ошибки к предсказанному приращению. Актор минимизирует квадрат предсказанной будущей стоимости; дополнительной одноступенчатой цели слежения нет.

## Взаимодействие с объектом

1. `predict(obs, reference, k)` вычисляет ограниченное управление и запоминает текущую ошибку.
2. `env.step(action)` делает шаг физической модели.
3. `learn(next_obs, reference, k)` предсказывает следующую ошибку **предыдущим идентификатором**, обновляет сети с целями по предыдущей политике и критику, затем добавляет измеренный переход в RLS — порядок Algorithm 1.
4. Между эпизодами вызывайте `reset()`: история переходов очищается, обученные веса, параметры RLS и прогресс обучения сохраняются.

Если внешняя логика изменила команду, передайте `applied_action=` в единицах выхода политики. Передавайте весь массив задания, включая следующий отсчёт. В примере F16 наблюдения выражены в радианах, команды — в градусах.

## Известное задание со скачками

В статье идентифицируется динамика ошибки при неизвестной динамике задания (раздел 3.3). Представление задания предполагает непрерывный, кусочно дифференцируемый сигнал. Если скачок команды напрямую включить в приращение ошибки, он может исказить оценку динамики самолёта.

Когда задание известно, включите явное **расширение для известного задания**:

```python
cfg = IMGDHPConfig(identifier_mode="output", history_length=4)
```

RLS идентифицирует приращения измеренного выхода и управления. При обновлении актора и критика прогноз ошибки равен `predicted_output - next_reference`. Входы сетей и стоимость по-прежнему содержат только ошибку слежения. Скачок команды исключается из идентификации объекта; опубликованные функции потерь и пути их дифференцирования сохраняются. Фактическое следующее измерение объекта не используется в прогнозируемой цели обучения.

Значение по умолчанию `identifier_mode="tracking_error"` сохраняет постановку статьи с неизвестной динамикой задания. Выбирайте режим до сбора переходов: его смена во время работы смешает истории разного смысла. Checkpoint сохраняет режим вместе с соответствующей историей.

## Параметры

| Параметр | Смысл |
| --- | --- |
| `identifier_mode` | Вход идентификатора: `tracking_error` (режим статьи по умолчанию) или `output` (расширение для известного задания). |
| `history_length` | Окно приращений M. Значение 1 — частный случай полного состояния; в уроке F16 используется 4. |
| `track_Q`, `control_R` | Диагональные неотрицательные веса ошибки и управления; по умолчанию R=0. |
| `obs_scale` | Масштаб каждого наблюдения. Сети и стоимость используют масштаб; RLS и lambda работают в физических координатах ошибки. |
| `beta_lambda` | Отношение весов потерь производной и J; beta статьи равна `1/(1+beta_lambda)`. Ноль оставляет обучение только по J. |
| `actor_lr`, `critic_lr` | Начальные шаги обучения. |
| `actor_lr_decay`, `critic_lr_decay` | Множители на каждом обновлении, по умолчанию 1. |
| `actor_lr_min`, `critic_lr_min` | Нижние границы шагов, по умолчанию 0. |
| `weight_limit` | Ограничение модулей весов, по умолчанию 20. |
| `forgetting`, `cov_init` | Коэффициент забывания RLS и начальная ковариация: положительный скаляр либо диагональ в порядке регрессора. |
| `actor_bias_input` | Постоянный вход ba актора из Eq. (64), по умолчанию 0.01; его масштаб влияет на обучение балансировочной команды. |
| `optimizer` | По умолчанию `sgd`; `adam` — дополнительный вариант. |
| `warmup_steps`, `critic_only_steps` | Начальный период идентификации и дополнительное обучение только критика. |
| `max_grad_norm` | Необязательное ограничение градиента; по умолчанию отключено. |
| `target_update_tau` | Необязательное сглаживание целевого критика; при 0 используется текущий критик. |

По разделу 5.2 начальные веса сетей лежат в `[-0.1, 0.1]`, блоки F единичные, G нулевые. Параметры настраиваются: значения по умолчанию и урок F16 **не воспроизводят** эксперимент статьи с частотой 1 кГц, её шумами, приводом и серией Монте-Карло. В уроке явно включены ограничение градиента, прогрев критика и масштабирование ошибки; шаги обучения подобраны для 100 Гц.

### Перенастройка обученного актора

`agent.retune_actor_inputs(feedback_gain=..., bias_input=...)` — метод SDK для воспроизводимого этапа настройки между опытами. `feedback_gain` умножает входные веса ошибки; смена постоянного входа обратно масштабирует его веса, сохраняя команду при нулевой ошибке. При единичном feedback gain сохраняется вся текущая политика, но меняется чувствительность её последующего обучения. Метод проверяет пределы весов, запрещает перенастройку при незавершённом переходе predict/learn и очищает моменты оптимизатора для преобразованного слоя. Новые веса и масштаб постоянного входа сохраняются в checkpoint.

Урок F16 вычисляет положительный шаг онлайн-SGD по локальным градиентам формулы (67), затем выполняет учебный эпизод нулевого задания. Это явно описанная экспериментальная процедура; в штатное обновление актора не добавляются PID или интегральная составляющая управления.

## Миграция и сохранение

В прежней реализации были независимые головы J/lambda, отсутствовала измеренная история, цель производной была неполной, а актор имел дополнительную цель слежения и штраф скорости управления. Старые контрольные точки отклоняются с сообщением о необходимости переобучения. Используйте `action_rate_penalty=0`; для стоимости управления предусмотрен `control_R`. Прежние шаги обучения нельзя переносить без проверки.

`save(path, save_gradients=True)` сохраняет сети, оптимизаторы, шаги обучения, RLS, историю и генератор возбуждения. Загрузка: `IMGDHPAgent.from_pretrained(path, load_gradients=True)`. Точное продолжение требует того же состояния среды, задания и номера шага. Новый эпизод начинайте с `reset()`.

## Границы проверки

Тесты сопоставляют производные с независимыми уравнениями и восстанавливают скрытую систему второго порядка по истории измерений. Прогон управления проверяет конкретный объект и сигналы. Это не доказательство глобальной устойчивости. В Remark 2 статьи прямо отмечено это ограничение; для некоторых начальных условий авторы также получили неудачные прогоны. Хорошее одноступенчатое предсказание нелинейного самолёта само по себе не подтверждает качество политики управления.

## Проверка переходного процесса

Полный урок F16 задаёт **только α** (`reference_size=1`, `tracking_indices=[0]`). Используются идентификация при известном задании и настройка чувствительностей, затем учебный эпизод нулевого задания. Основная ступенька начинается на 20-й секунде, полная длительность — 38 с; качество оценивает `ControlBenchmark`. **Пересчитанный результат, seed 0:** максимальная ошибка нулевого участка **0.000120°**, ошибка хвоста на 38 с **+0.000212°**, перерегулирование **4.50%**, установление в полосе задания **3.38 с**, **CPI 0.9237**. Все 12 проверок seed/амплитуда прошли условие точности 0.1% за последние пять секунд 60-секундного опыта. В последовательности команд конечные остатки больше: наибольшее среднее по последним пяти секундам около 0.00192°. Это измеренные ошибки конечного горизонта, а не утверждение о математически точном нуле для любого сигнала.

### Масштаб начальной ковариации RLS

`cov_init` принимает также `M * (n_tracked + n_action)` диагональных элементов: сначала все блоки истории приращений состояния, затем все блоки истории управления. Например, для двух измерений в радианах, команды в градусах и M=4:

```python
scale = 180 / np.pi
covariance_diagonal = (1e4 * scale**2,) * 8 + (1e4,) * 4
cfg = IMGDHPConfig(track_Q=(1.0, 0.0), history_length=4,
                  cov_init=covariance_diagonal, actor_bias_input=0.01)
```

Такой prior эквивалентен RLS в нормированных координатах с начальной ковариацией `1e4 * I`. Предсказания SDK остаются в физических единицах. Это не гарантия сходимости. Тесты проверяют эквивалентность смены единиц, сброс ковариации и продолжение из checkpoint. Прежние значения по умолчанию сохранены.

**Границы результата:** обновлённые проверки ступенек, амплитуд, seed, поздней команды и последовательности переключений сохраняют адаптацию. На 500 с α и управление численно ограничены, но накапливается большой тангаж; это не проверка нелинейного полёта. Синус амплитудой 2° и периодом 4 с пока отслеживается неточно (RMSE за 12 с — 1.685°). Эти опыты не доказывают устойчивость для произвольных сигналов и начальных состояний.
