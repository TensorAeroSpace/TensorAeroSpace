# Подбор контроллера по настройкам среды

Основной вход — `ControllerTuner`: среда, её настройки, ступеньки по одному или нескольким состояниям, контроллер и метод поиска. Метрика по умолчанию — CPI. Создание объектов, обучение, моделирование и оценку выполняет библиотека.

```python
from tensoraerospace.optimization import ControllerTuner, Step

tuner = ControllerTuner(
    env="NonlinearB737-v0",
    env_kwargs={"trim_at": (10000.0, 600.0), "dt": 0.02},
    reference={"theta": Step(1.0, at=20.0, unit="deg")},
    controller="aa_indi",
    method="genetic",
    duration=40.0,
    method_options={"population_size": 8},
    seed=42,
)
result = tuner.optimize(n_trials=32)
print(result.best_params, result.best_value)
result.plot_response()
result.plot_history()
```

[Полный выполненный урок: AA-INDI, нелинейный B737, несколько заданий и проверка](../example/optimization/example_optimization.md).

## Настройки эксперимента

| Настройка | Значение |
|---|---|
| `env` | Зарегистрированный ID Gymnasium или поддерживаемый класс среды, не готовый экземпляр |
| `env_kwargs` | Штатные настройки среды: `dt`, начальное состояние/балансировка, физические отказы |
| `reference` | Словарь «имя физического состояния → Step»; одна ступенька на канал |
| `Step(amplitude, at=20, initial=None, unit="native")` | Амплитуда — приращение; время в секундах; исходный уровень по умолчанию равен начальному состоянию |
| `unit` | `native`, `rad`, `deg`; для угловых скоростей преобразование означает rad/s ↔ deg/s |
| `duration=40` | Полный горизонт, секунды; время ступеньки и длительность кратны `dt` |
| `controller` | Имя/алиас или поддерживаемый класс штатного агента |
| `metric="cpi"` | Минимизируемая метрика; также `iae`, `ise`, `itae`, `relative_tail_error`, `theta.cpi` и другие |
| `normalize=True` | Нормирование каждого канала по собственной амплитуде перед расчётом бенчмарка |
| `constraints={}` | Верхние включительные границы метрик для каждого seed; отсутствие времени установления нарушает его ограничение |
| `state_limits={}` | Дополнительные физические границы, например `{"alpha": (-0.2, 0.2)}` в единицах состояния |
| `seeds=(0,)` | Одинаковый набор seeds обучения/моделирования для всех кандидатов; оценки усредняются |
| `seed=0` | Seed алгоритма поиска |
| `training_episodes=0` | Предварительные эпизоды обучения; веса сохраняются в финальный оцениваемый эпизод, где обучение продолжается |
| `torch_threads=1` | Число потоков Torch CPU на моделирование; `None` сохраняет текущую настройку |
| `controller_options={}` | Фиксированные настройки профиля; список: `ControllerTuner.profile(name)` |
| `search_space=None` | Готовые диапазоны; свои задаются через `Float`, `Int`, `Categorical` |

`reference_signal` и `number_time_steps` не нужно передавать в `env_kwargs`: они формируются из задания и длительности. Траектория включает начальное и конечное время. NaN/Inf, выход за область модели и досрочное завершение исключают кандидата. Проверяются все физические состояния. Для Boeing область малых манёвров: крен/тангаж ±30°, скорость 250–1000 ft/s, высота от 0 до 50 000 ft; для F16 также ограничены углы и угловые скорости.

Общий CPI — среднее CPI каналов, остальные общие показатели используют худшее (максимальное) значение. Индивидуальные ключи: `theta.cpi`, `phi.relative_tail_max_error` и т. п. Ошибка удержания до ступеньки не входит в штатный CPI после ступеньки: при необходимости ограничьте `pre_step_relative_error`.

## Методы поиска

| `method` | Алгоритм | Пример `method_options` |
|---|---|---|
| `"tpe"` — по умолчанию | TPE из Optuna | `{"n_startup_trials": 5}` |
| `"annealing"` | Отжиг: правило Метрополиса, геометрическое охлаждение, отражение от границ | `{"temperature": 1.0, "cooling": 0.95, "step_size": 0.2}` |
| `"genetic"` | NSGA-II из Optuna с одной минимизируемой метрикой | `{"population_size": 8, "mutation_prob": 0.3}` |
| `"random"` | Случайный поиск с seed | `{}` |

Отжиг работает с логарифмическими, целочисленными и категориальными параметрами. Отклонённый прогон не становится принятым состоянием цепочки. Генетическому методу нужен бюджет больше одной популяции завершённых кандидатов. По умолчанию поиск последовательный; TPE, генетический и случайный поиск поддерживают `n_jobs>1`. Горизонт и бюджет обучения одинаковы. Неполная траектория не может победить.

`optimize(n_trials=30, timeout=None, target=None, patience=None, initial_params=None, show_progress_bar=True, n_jobs=1)` запускает новое исследование. `initial_params` — полный или частичный словарь искомых параметров, оцениваемый первым; остальные значения выбирает метод поиска. `target` и `patience` позволяют остановиться раньше. Таймаут проверяется между испытаниями. Если все кандидаты отклонены, возникает ошибка; причины доступны через `tuner.diagnostics()` и в `tuner.optimizer.study.trials`.

Описание алгоритмов: [NSGA-II в Optuna](https://optuna.readthedocs.io/en/v3.6.2/reference/samplers/generated/optuna.samplers.NSGAIISampler.html), [пример собственного sampler и отжига](https://optuna.readthedocs.io/en/v3.6.2/tutorial/20_recipes/005_user_defined_sampler.html). Здесь реализован обычный simulated annealing, а не dual annealing из SciPy.

## Ускорение поиска на нескольких ядрах CPU

Передайте `n_jobs`, чтобы независимые кандидаты выполнялись в отдельных процессах. Поддерживаются все восемь профилей контроллеров и методы поиска `tpe`, `genetic`, `random`:

```python
from tensoraerospace.optimization import ControllerTuner, Step

tuner = ControllerTuner(
    env="NonlinearB737-v0",
    env_kwargs={"trim_at": (10000.0, 600.0), "dt": 0.02},
    reference={"theta": Step(1.0, at=20.0, unit="deg")},
    controller="ihdp",
    method="tpe",
    duration=40.0,
    seed=42,
    torch_threads=1,  # По умолчанию: один поток Torch CPU на моделирование
)
result = tuner.optimize(n_trials=120, n_jobs=4, target=3.7)
print(result.best_params, result.best_value)
result.plot_response()
```

В Jupyter запускайте ячейку напрямую. В Python-скрипте поместите создание tuner и вызов `optimize()` внутрь `if __name__ == "__main__":`. Процессы импортируют установленную библиотеку; после её обновления перезапустите ядро ноутбука. Настройки должны поддерживать pickle: используйте классы/функции из импортируемых модулей вместо локальных callback-функций ноутбука или lambda. Для очень коротких прогонов оставьте `n_jobs=1`: запуск процессов может стоить дороже расчёта.

Для каждого кандидата создаются отдельная среда, адаптивные веса и состояние генераторов случайных чисел. Ступенька, dt, длительность, бюджет обучения, проверки физики и жёсткие ограничения совпадают с последовательным режимом. Исследованием Optuna управляет только родительский процесс. Отдельные процессы исключают взаимное перезаписывание Torch/NumPy seeds кандидатами. `torch_threads=1` ограничивает число потоков Torch CPU для небольших сетей; `None` сохраняет исходную настройку каждого процесса. После моделирования, в том числе при ошибке, число потоков вызывающего процесса восстанавливается. Эта настройка не управляет потоками NumPy/BLAS.

Одновременно предлагается не более `n_jobs` кандидатов. Результаты записываются в порядке номеров испытаний, поэтому поиск воспроизводим при том же числе процессов и детерминированных численных вычислениях. В параллельном TPE по умолчанию включён `constant_liar=True`, чтобы не предлагать близкие к уже запущенным кандидатам параметры; настройку можно переопределить в `method_options`. Пакет видит меньше завершённых результатов, чем последовательный поиск такой же длины: изменение `n_jobs` может изменить кандидатов и итоговый CPI. Ускорение вычислений не гарантирует уменьшения числа попыток до цели. Основа запуска — [пакетный интерфейс ask-and-tell Optuna](https://optuna.readthedocs.io/en/stable/tutorial/20_recipes/009_ask_and_tell.html).

Кандидат из `initial_params` завершается до запуска первого пакета. `target`, `patience` и `timeout` останавливают запуск следующего пакета; уже отправленные кандидаты завершаются. Поэтому ранняя остановка может выполнить до `n_jobs - 1` дополнительных попыток. Прогресс обновляется при записи результатов по номерам испытаний. `result.save(...)` сохраняет число процессов/потоков и время расчёта в каждом worker. После поиска выбранный кандидат автоматически моделируется повторно.

Отжиг требует `n_jobs=1`: следующая точка зависит от принятия предыдущей. Для параллельного поиска выберите TPE или генетический метод. Если уже есть проверенные параметры для того же эксперимента, передайте `initial_params=previous_result.best_params`. `optimize()` создаёт новое исследование. Чтобы сохранить всю историю и состояние метода поиска, используйте `resume()`, описанный ниже.

Замер: 24 одинаковых кандидата случайного поиска, iHDP на нелинейном B737, ступенька тангажа 1° с 20 с, dt=0,02 с, длительность 40 с. Два последовательных запуска заняли в среднем **44,7 с**, четыре процесса — **14,9 с**, включая запуск процессов и повторную проверку победителя. Ускорение на тестовой машине — примерно **3 раза**. Метрики всех кандидатов и траектории состояний/управлений победителя совпали точно. Это сравнение времени на одинаковых кандидатах; скорость и качество политики в других экспериментах могут отличаться.

## Поиск лучшего найденного переходного процесса

`find_best_response()` минимизирует метрику на заданном бюджете: первый вызов начинает исследование, последующие продолжают его. Оптимизируется выбранная метрика (`cpi` по умолчанию), без порога досрочной остановки по целевому значению.

```python
# Начальный поиск: среда, контроллер, метрика и ограничения уже заданы в tuner.
result = tuner.find_best_response(n_trials=120, n_jobs=8)

# Ещё 120 кандидатов в том же исследовании, с прежними восемью процессами.
result = tuner.find_best_response(n_trials=120)
print(result.best_params, result.best_value)
result.plot_response()
result.plot_history()
```

Полная сигнатура: `find_best_response(n_trials=30, timeout=None, patience=None, initial_params=None, show_progress_bar=True, n_jobs=None)`. Таймаут и необязательный patience могут остановить дополнительный бюджет раньше. Цель из предыдущего `optimize(target=...)` не переносится. `n_jobs=None` означает один процесс для нового поиска либо прежнее число процессов при продолжении. Используются те же нативный контроллер, метод поиска и бенчмарк; формула CPI не меняется.

Возвращается минимальная **измеренная допустимая** оценка по всей истории. Все заданные `constraints` и проверки физики сохраняются. Если допустимых кандидатов нет, метод выдаёт обычную ошибку с диагностикой и не ослабляет требования. Изменение условий эксперимента требует нового исследования, как и при `resume()`.

Для минимизации только CPI без ограничений на точность явно создайте отдельный `ControllerTuner(..., metric="cpi", constraints={})`. Он может выбрать процесс, который не достигает желаемой точности: перед принятием результата проверьте время установления относительно задания, перерегулирование, ошибку в конце и до ступеньки. Новое исследование не переносит решения об отклонении кандидатов из прежнего поиска с ограничениями. Проверки области модели и приводов сохраняются.

Конечный бюджет не гарантирует глобальный минимум или CPI=0. Дополнительные попытки могут улучшить оценку либо оставить её прежней. `find_best_response()` подбирает параметры выбранного контроллера; автоматического сравнения типов контроллеров здесь нет. В [выполненном примере AIDI/B737](../example/optimization/example_optimization.md) показаны продолжение, оба варианта ограничений и checkpoint.

## Продолжение поиска и checkpoint

`resume()` добавляет бюджет попыток к тому же исследованию. Сохраняются завершённые и отклонённые испытания, лучший допустимый результат, генератор случайных чисел и состояние метода поиска. TPE использует накопленную историю, генетический поиск сохраняет популяцию/историю, отжиг — принятую точку и текущую температуру.

```python
# Один раз запускаем поиск (tuner создан с method="tpe").
result = tuner.optimize(n_trials=120, n_jobs=8)

# ЕЩЁ до 120 кандидатов; остаются прежние восемь процессов.
result = tuner.resume(n_trials=120)
# Эквивалентная запись: result = result.resume(n_trials=120)

print("Всего попыток:", len(result.study.trials))
print("Лучшие параметры:", result.best_params)
print("Лучший CPI:", result.best_value)
result.plot_history()  # Вся история, включая первый запуск
result.plot_response()
```

`resume(n_trials=30, timeout=None, target=None, patience=None, initial_params=None, show_progress_bar=True, n_jobs=None)` использует прежнее исследование. `n_trials`, таймаут и patience задают новый бюджет текущего вызова. `target` проверяется по лучшему результату всей истории: если цель уже достигнута, новые кандидаты не запускаются. Для дальнейшего поиска уберите `target` или задайте меньшее значение. Прогресс считает только новые попытки, а прежний лучший результат показывает сразу.

`n_jobs=None` сохраняет прежнее число процессов. Его можно изменить явно, в том числе переключиться между последовательным и параллельным выполнением; настройки и состояние метода поиска сохраняются. Изменение размера пакета может изменить следующие предложения адаптивного метода. Отжиг по-прежнему требует один процесс. При детерминированных численных вычислениях продолжение с границы пакета и тем же числом процессов сохраняет последовательность кандидатов. Разделение внутри пакета может изменить момент получения обратной связи TPE/генетическим методом.

Среда, порядок заданных каналов, длительность, dt, контроллер, фиксированные параметры, пространство поиска, метрика, ограничения, seeds, бюджет обучения и настройки метода должны оставаться прежними. `resume()` обнаруживает изменения до запуска испытаний. Для другого эксперимента создайте новый tuner/поиск. Новый вызов `optimize()` заменяет активное исследование; результат старого исследования не сможет случайно продолжить новое. После продолжения присвойте возвращённый результат переменной заново, чтобы использовать обновлённые лучшие параметры и траекторию.

### Продолжение после перезапуска Jupyter

```python
# Перед остановкой ядра:
tuner.save_checkpoint("ihdp-search.pkl")
# Эквивалентная запись: result.save_checkpoint("ihdp-search.pkl")
```

```python
# В новом ядре:
from tensoraerospace.optimization import ControllerTuner

tuner = ControllerTuner.load_checkpoint("ihdp-search.pkl")
result = tuner.resume(n_trials=200, target=3.7)
```

Checkpoint содержит настройки эксперимента, все испытания, состояние метода поиска и его RNG, число процессов. Загрузка не запускает моделирование. Сохранение заменяет файл атомарно. Сохраняйте после остановки поиска; это работает и после `No feasible trial completed`, сохраняя историю отказов и исходные ограничения. `resume()` не ослабляет невыполненные ограничения.

Checkpoint использует pickle: загружайте собственные доверенные файлы в совместимом окружении Python/SDK/Optuna с импортируемыми настройками. `result.save("report.json")` остаётся переносимым отчётом о метриках и параметрах; этот JSON не является checkpoint для продолжения. Эти методы продолжают **оптимизацию параметров**. Каждый кандидат по-прежнему создаёт новый контроллер с тем же протоколом онлайн-обучения; обученные веса выбранной нейросети в checkpoint не сохраняются.

## Прогресс поиска

В `ControllerTuner.optimize`, `ControlOptimizer.optimize` и `AgentClass.optimize` прогресс включён по умолчанию. В Jupyter используется виджет, если он доступен, в терминале — текстовая шкала. В строке показаны число завершённых испытаний и бюджет, прошедшее время, ETA, лучший допустимый результат с номером испытания и число отклонённых кандидатов. Пока никто не прошёл все ограничения, выводится `no feasible trial`.

```python
result = tuner.optimize(n_trials=100, target=0.6, show_progress_bar=True)
# Для запуска без прогресс-бара:
# result = tuner.optimize(n_trials=100, show_progress_bar=False)
```

ETA появляется после первого завершённого испытания и обновляется по мере завершения следующих. Это оценка времени до исчерпания бюджета; досрочная остановка и разная длительность испытаний могут её изменить. Повторный прогон выбранного контроллера выполняется после поиска и в ETA не входит. При досрочной остановке сохраняется фактический счётчик, например 8/100, указывается причина остановки и обнуляется оставшееся время. Отклонённые кандидаты учитываются в прогрессе, но не становятся лучшим результатом. Вывод прогресса не зависит от уровня логирования Optuna.

## Если ни один кандидат не прошёл ограничения

`constraints={"cpi": 0.6}` требует CPI ≤ 0,6 для каждого оцениваемого seed/сценария. Если все кандидаты превышают этот порог, оптимизатор выдаёт ошибку. CPI — взвешенная сумма ISE, ITAE и перерегулирования; `normalize=True` нормирует амплитуду ступеньки, **а не CPI в диапазон [0, 1]**. Ограничение CPI не означает процент относительной ошибки.

Теперь ошибка показывает нарушенные границы, количество оценённых случаев и минимальные наблюдавшиеся значения. В примере со ступенькой тангажа B737 поиск из 12 испытаний с порогом 0,6 получил минимум CPI 3,30518: все 12 кандидатов нарушили границу. Это результат данного поиска, а не доказательство недостижимости 0,6 при другой настройке контроллера.

После ошибки можно получить подробности без повторного моделирования:

```python
tuner.diagnostics()
```

В словаре доступны состояния испытаний, `upper_bound`, `violating_cases`, `evaluated_cases`, `lowest_observed` для каждого ограничения и причины отклонения. `lowest_fully_evaluated` учитывает только испытания, которые прошли все заданные seeds/сценарии и получили конечную целевую метрику. Допустимость указана явно; отклонённый кандидат не становится успешным результатом. Минимумы разных показателей могут относиться к разным кандидатам.

Если 0,6 — желаемая цель остановки, а после исчерпания бюджета нужен лучший допустимый результат, создайте tuner без жёсткого ограничения CPI и запустите `tuner.optimize(n_trials=100, target=0.6)`. Остальные ограничения сохраняются; возвращённый CPI может быть выше 0,6. Если порог обязателен, сохраните его и пересмотрите параметры поиска/контроллера. Диагностика не меняет заданные границы.

## Контроллеры и адаптеры

| Профиль | Среды и область применения | Искомые параметры по умолчанию |
|---|---|---|
| `aa_indi` | Нелинейные B737/B747; `phi`, `theta`, `psi`, `p`, `q`, `r` | `rate_gain`, `cutoff_hz`, `outer_gain`, `covariance_init` |
| `aidi` | Те же самолёты/состояния; штатный вход задания угловой скорости | `rate_gain`, `cutoff_hz`, `outer_gain`, `rls_cov_init`, `config.rls_sigma0` |
| `iadp` | Линейные F16/B747, стандартные нелинейные F16/B737/B747 | `gamma`, `forgetting`, `control_weight`, `track_weight`, `phi_init`, `policy_eval_every` |
| `imgdhp` / `im_gdhp` | Те же физические среды | `actor_lr`, `critic_lr`, `history_length`, `track_weight`, `control_weight`, `config.gamma`, `config.beta_lambda`, `config.forgetting` |
| `et_dhp` | Те же физические среды | `actor_lr`, `critic_lr`, `rho`, `track_weight`, `control_weight`, `config.trigger_floor`, `config.gamma` |
| `ihdp` | Те же среды; один эпизод с обучением | `actor_lr`, `critic_lr`, `track_weight`, `gamma`, `hidden_size`, `excitation_amplitude`, `actor_settings.learning_rate_decay`, `critic_settings.learning_rate_decay` |
| `mpc` | Те же среды; номинальная линейная модель прогноза | `horizon`, `control_weight`, `track_weight`, `terminal_weight`, `lr` |
| `hdp` | Только `ImprovedB747-v0`, `theta` | `actor_lr`, `critic_lr`, `gamma`, `hidden_size`, `exploration_std` |

Неподдерживаемые сочетания отклоняются явно. Профили состояний Boeing используют девять каналов скоростей, угловых скоростей и ориентации; перемещающиеся земные координаты исключены. Наведение по позиции не реализовано. Угловой F16 — стандартные 14 состояний, три поверхности и постоянная тяга. Продольный F16 — физические наблюдения без метаданных отказа и пользовательской функции feedforward. Для AA-INDI/AIDI нельзя одновременно задавать угол и соответствующую угловую скорость по одной оси.

В профилях состояний вычитается начальное физическое состояние, углы/скорости масштабируются по одному градусу, а заданные каналы — по амплитуде ступеньки. Приращения команд нормируются относительно балансировочного управления. Ограничения объекта и приводов сохраняются. Наблюдения самой среды и аэродинамические уравнения не меняются. Балансировку F16 и `control_bias` нужно задать в настройках среды. Для профилей с номинальной моделью нужен ненулевой якобиан входа за один шаг: включите состояния привода либо используйте RK4. При сокращённом наблюдении ненаблюдаемые состояния в исходной модели фиксируются на балансировке.

iADP получает локальную модель исправного объекта и начальную оценку функции ценности из дисконтированного уравнения Риккати; затем RLS и оценка политики продолжаются. IM-GDHP использует документированное расширение `identifier_mode="output"` для известного разрывного задания. ET-DHP предварительно обучает модель на номинальных переходах (`model_samples=512`, `model_epochs=200`); actor/critic продолжают учиться по событиям. `online_model_fit=True` включает дополнительное обучение модели. MPC использует фиксированную номинальную линейную модель без предварительного знания будущих ступенек. Внешний контур угла AA-INDI/AIDI: 0,35 с⁻¹, ограничение заданной угловой скорости 3°/с, скорости команды поверхности 20°/с. Внутренняя идентификация активна весь прогон.

Это прикладные профили со стартовыми настройками, без гарантии качества политики на любой среде и без замены опубликованных уравнений обучения.

print(ControllerTuner.available_controllers())
print(ControllerTuner.profile("iadp"))

## Поиск по всем активным настройкам контроллера

Прежние два параметра iHDP были узким набором для поиска, а не полным набором настроек алгоритма. Теперь автоматический поиск iHDP меняет **восемь параметров**: начальные шаги обучения и коэффициенты их убывания, gamma, вес ошибки, ширину скрытого слоя и амплитуду возбуждения. У остальных контроллеров автоматические пространства также расширены — они перечислены выше. В `search_space` можно выбрать любую активную настройку или нативный путь, а не только параметры из пространства по умолчанию. Одновременный поиск по всем параметрам обычно неэффективен: выбирайте группы, связанные с наблюдаемой ошибкой.

### iHDP: архитектура, стоимость, обучение и идентификация

```python
from tensoraerospace.optimization import ControllerTuner, Step, Float, Int, Categorical

profile = ControllerTuner.profile("ihdp")
print(profile["search_space"])          # automatic search ranges
print(profile["tunable_parameters"])   # shortcuts + native constructor paths

space = {
    "actor_lr": Float(1e-4, 0.3, log=True),
    "critic_lr": Float(1e-4, 0.1, log=True),
    "gamma": Float(0.8, 0.999),
    "track_weight": Float(0.1, 10.0, log=True),
    "actor_settings.layers.0": Int(4, 32, step=4),
    "critic_settings.layers.0": Int(4, 32, step=4),
    "actor_settings.activations.0": Categorical(["tanh", "relu"]),
    "actor_settings.learning_rate_decay": Float(0.995, 1.0),
    "critic_settings.learning_rate_decay": Float(0.995, 1.0),
    "actor_settings.learning_rate_min": Float(1e-7, 1e-5, log=True),
    "critic_settings.learning_rate_min": Float(1e-8, 1e-5, log=True),
    "warmup_steps": Int(5, 40),
    "excitation_amplitude": Float(0.001, 0.03, log=True),
    "actor_settings.pulse_length_3211": Int(5, 100),
    "incremental_settings.window_size": Int(20, 60, step=5),
    "actor_settings.WB_limits": Float(1.0, 10.0),
    "critic_settings.WB_limits": Float(1.0, 10.0),
}

tuner = ControllerTuner(
    env="NonlinearB737-v0",
    env_kwargs={"trim_at": (10000.0, 600.0), "dt": 0.02},
    reference={"theta": Step(1.0, at=20.0, unit="deg")},
    controller="ihdp",
    method="tpe",  # also: annealing, genetic, random
    metric="cpi",
    duration=40.0,
    search_space=space,
    seed=42,
)
result = tuner.optimize(n_trials=120, target=3.7)
print(result.best_params)
print(result.best_value, result.best_value <= 3.7)
result.plot_response()
```

Это пример настройки поиска, а не обещание получить CPI ≤ 3.7 за 120 испытаний. Обязательный порог задаётся через `constraints={"cpi": 3.7}`; `target=3.7` позволяет вернуть лучший найденный результат, даже если цель не достигнута. Объект, ступенька и окно оценки одинаковы во всех испытаниях.

Квадратичная стоимость Q, дисконт gamma, параметры сетей и идентификация входят в исходную архитектуру IHDP ([Zhou et al., IMAV 2016](https://www.imavs.org/papers/2016/25.pdf), уравнения 2, 7, 12, 35). Коэффициенты убывания и минимальные шаги настраивают существующее численное расписание реализации; они не выдаются за константы из статьи. Убывание больше не повышает выбранный шаг выше его начального значения. Окно МНК должно содержать не меньше `число состояний + число входов` отсчётов; достаточная длина сама по себе не гарантирует информативность данных.

### Нативные пути и используемые режимы

| Контроллер | Дополнительные группы параметров / примеры путей |
|---|---|
| AA-INDI | Усиление и ограничение скорости внешнего контура; `config.sigma0`, `config.forgetting_min`, `config.covariance_init`, `config.rate_feedback.1`; шумы, дрейф и `config.observer.hosm_gains.0` наблюдателя |
| AIDI | Внешний контур; `config.rls_lambda_min`, `config.rls_lambda_max`, `config.rls_memory_length`, `config.rls_sigma0`, согласованность идентификации, фильтр и распределение управления |
| iADP | `config.Q.0.0`, `config.R.0.0`, ковариация и забывание RLS, окно, период, итерации и прогрев критика. Начальная оценка Риккати пересчитывается с выбранными Q, R и gamma |
| IM-GDHP | Архитектура актора/критика, gamma, Q/R, `config.beta_lambda`, история, ковариация и забывание, расписания обучения, оптимизатор, возбуждение, прогрев, сглаживание целей, ограничения градиента и весов |
| ET-DHP | Архитектуры и шаги актора/критика/модели, Q/R, gamma, порог событий, бюджет обучения модели, режим дообучения, число обновлений по событию, масштаб инициализации |
| iHDP | Отдельные слои и активации актора/критика, Q, gamma, расписания, прогрев, возбуждение, ограничения весов и окно идентификации |
| HDP | Шаги обучения, ширина сети, возбуждение, gamma, собственные веса стоимости и циклы обучения актора/критика по эпизодам. Для собственных весов нужно `controller_options={"dhp_use_env_cost": False}` |
| MPC | Горизонт, веса ошибки/управления/изменения управления, терминальный вес, шаг и итерации решателя, оптимизатор, использование предыдущего решения и выбор лучшей итерации |

`ControllerTuner.profile(name)["native_parameters"]` показывает поддерживаемые пути конструктора. Числовые компоненты пути адресуют элементы векторов/матриц: `config.Q.0.0`, `weights.S_diag.0`, `actor_settings.layers.0`. Через `controller_options` задавайте фиксированную структуру, через `search_space` — изменяемые элементы. Например, `controller_options={"actor_hidden": (16, 8)}` вместе с `search_space={"actor_settings.layers.0": Int(8, 32, step=8)}` меняет только первый скрытый слой. Размеры выходов сетей должны соответствовать среде.

Фиксированные настройки исключаются из автоматического поиска вместе с их короткими именами. Явное пространство поиска может переопределить тот же нативный ключ либо отдельный его элемент. Два имени одного параметра одновременно искать нельзя: например, `actor_lr` и `actor_settings.learning_rate` приведут к понятной ошибке. `initial_params` может быть неполным: остальные значения первого испытания выберет метод поиска.

Профили показывают параметры используемого цикла управления. AIDI в режиме `predict_rates` обходит контуры C*/крена/скольжения/скорости и PCH, поэтому их настройки здесь не предлагаются. Каскадный iHDP и iHDP с интегратором, офлайн/последовательные протоколы iADP и дополнительный базовый регулятор HDP требуют явного исследовательского протокола через `AgentClass.optimize`. dt, seeds, размерности, геометрия самолёта и физические ограничения приводов относятся к условиям эксперимента. Уравнения объекта не изменяются.

## Результат и повторный прогон

`tuner.simulate()` моделирует профиль по умолчанию; `tuner.simulate(params, seed=17)` — выбранные параметры без поиска. Возвращается `ControlRun`: физические массивы `time`, `reference`, `output`, отправленные в среду команды `actions`, имена/единицы `states`/`units` и `metrics`. У команд одна строка на переход.

`result.best_params`, `best_value`, `study`, `best_run` содержат параметры, оценку, исследование и повторный прогон на первом seed. При нескольких seeds `best_value` — средняя оценка, которая может отличаться от CPI этого прогона. `result.simulate(seed=17)` заново создаёт и обучает выбранный профиль; сохранённые веса политики не загружаются. `result.plot_response(baseline=baseline)` сравнивает одинаковые эксперименты. `result.save(path)` сохраняет параметры, протокол и историю испытаний в JSON.
