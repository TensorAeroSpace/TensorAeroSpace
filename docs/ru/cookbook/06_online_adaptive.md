# Рецепт 06 — Запуск и диагностика онлайн-адаптивного регулятора

**Цель:** пройти с iADP путь от идентификации до замкнутого управления, сохранить
адаптацию при неизвестном изменении объекта и проверить одновременно слежение
и оценённую модель. Пример полный: выполняйте блоки Python по порядку из корня
репозитория в установленном окружении проекта.

Начните с простого объекта, чтобы разобраться с последовательностью измерений,
затем переходите к [AA-INDI на B737](14_aaindi.md) или
[сравнению на B747 с отказом](09_fault_tolerance.md). Здесь моделируются 80 секунд
с шагом 1 мс; это шаг симуляции, а не обещание работы Python в реальном времени.

## 1. Выберите измерения и интерфейс

Общая идея онлайн-адаптивных агентов: **измерить → вычислить команду → применить
→ измерить новое состояние → обновить модель**. Требования к входам различаются:

| Агент | Вход регулятора и обновление |
|---|---|
| [iADP](../agent/iadp.md) | Вектор состояния объекта и состояние генератора задания; RLS-модель и квадратичный критик. |
| [AA-INDI](../agent/aa_indi.md) | `FlightMeasurement`: IMU в СИ, независимая навигация и фактические рули; идентификация физических моментов и наблюдатель датчиков. |
| [IHDP](11_ihdp.md) / [IM-GDHP](12_imgdhp.md) | Состояние и задание, нейросетевые актор/критик и идентифицируемая модель; конструкторы приведены в отдельных рецептах. |
| [ET-DHP](13_etdhp.md) | Состояние и задание, событийное обновление актора и критика; собственные правила времени обновления. |

У iADP `n_state` — число измеряемых состояний объекта, а не приводов. Размер
состояния генератора задания можно задать отдельно через `n_reference` и матрицы
выходов. У AA-INDI одна скорость тангажа не заменяет независимые измерения скорости
и ориентации, необходимые наблюдателю.

## 2. Задайте известный объект и этап идентификации

Используем точное дискретное решение
\(\dot{x}=-2x+\eta u\). Здесь \(x\) — угловая скорость в рад/с, \(u\) — скалярное
управление, а эффективность объекта \(\eta\) меняется с 1 до 0.7 на 60-й секунде.
Задание постоянно и равно 0.05 рад/с. Изменение эффективности задаётся только
в симуляторе объекта.

Без начальной оценки входного коэффициента iADP нужны информативные изменения
управления. Две синусоиды возбуждают объект первые 20 с. После этого остаётся
меньшее периодическое возбуждение. Регулятор не получает истинные коэффициенты
`a`, `b`, эффективность или время отказа.


```python
import numpy as np
import matplotlib.pyplot as plt
from tensoraerospace.agent.iadp import IADPAgent, IADPConfig

dt, duration = 0.001, 80.0
steps = round(duration / dt)
time = np.arange(steps + 1) * dt
identification_time = np.arange(round(20.0 / dt)) * dt
excitation = (
    0.15 * np.sin(2 * np.pi * 0.7 * identification_time)
    + 0.05 * np.sin(2 * np.pi * 1.7 * identification_time)
)[:, None]
period = np.arange(round(10.0 / dt)) * dt
ongoing_excitation = (0.015 * np.sin(2 * np.pi * 0.7 * period))[:, None]

config = IADPConfig.paper(
    excitation_signal=excitation, dt=dt, learning_mode="continuous",
    Q=np.array([[100.0]]), R=np.array([[0.0001]]),
    gamma=0.95, gamma_rls=0.999, phi_init=1e6,
    u_magnitude_limit=0.5, u_rate_limit=2.0,
    continuous_excitation_signal=ongoing_excitation,
)
agent = IADPAgent(n_state=1, n_control=1, config=config)
reference = np.array([0.05])
x = np.zeros(1)
a = np.exp(-2 * dt)
b = -np.expm1(-2 * dt) / 2
```


`IADPConfig.paper` задаёт расписание начальной идентификации и критика: 20 с
обучения модели, окно переходов 20 с и вычисление критика на частоте 20 Гц.
Значения Q, R, ковариации и возбуждения выше относятся к этому проверочному
скалярному примеру; это не универсальные настройки самолёта.

| Параметр | Смысл в этом примере |
|---|---|
| `Q`, `R` | Веса ошибки слежения и фактического управления. При смене единиц нужно пересмотреть веса. |
| `gamma` | Дисконт Беллмана в политике и критике. |
| `gamma_rls` | Забывание RLS за отсчёт; 1 убирает забывание, но **не замораживает идентификацию**. |
| `phi_init` | Начальная ковариация RLS; большие значения допускают более сильные ранние обновления параметров. |
| `learning_mode="continuous"` | Позволяет обновлять модель и критик после инициализации. |
| `u_rate_limit` | Изменение входа за секунду; за отсчёт умножается на `dt`. |

Периодическое возбуждение добавляется к приращению политики и проходит через те же
ограничения входа. Его удаление меняет эксперимент. Постоянное задание всё ещё
может вызвать информативный переходный процесс, но установившаяся неизменная
траектория обычно не позволяет определить все коэффициенты модели.

## 3. Выполняйте одно обновление на физический переход

`predict` возвращает ограниченную **команду входа**, хотя внутри политики
вычисляется приращение. Примените её один раз. Затем передайте в `learn` новое
измерение и фактический вход. Здесь привод точно выполняет команду; изменение
эффективности находится дальше, в динамике объекта.


```python
states, actions, estimates = [x[0]], [], []
for k in range(steps):
    command = agent.predict(x, reference, k)
    actual_input = command.copy()
    # Plant-only effectiveness change; the agent never receives this schedule.
    effectiveness = 1.0 if time[k] < 60.0 else 0.7
    x = a * x + b * effectiveness * actual_input
    diagnostics = agent.learn(x, reference, k, applied_action=actual_input)
    if not np.isfinite(x).all() or not np.isfinite(agent.P).all():
        raise RuntimeError(f"Non-finite state or critic at step {k}")
    states.append(x[0])
    actions.append(actual_input[0])
    estimates.append(agent.G[0, 0])

states, actions, estimates = map(np.asarray, (states, actions, estimates))
assert agent.rls.num_updates == steps - 1
print("RLS updates:", agent.rls.num_updates, "phase:", agent.phase)
print("Identified / true final G:", estimates[-1], 0.7 * b)
```


На первом переходе ещё нет предыдущего приращения состояния, поэтому обновления
RLS нет. Ожидаются **79,999** обновлений на 80,000 переходов. Критик обновляется
с заданной периодичностью после накопления достаточной истории.

Для меняющегося задания передавайте полный массив задания и один и тот же `k`
в оба вызова: `predict` использует отсчёт `k`, а `learn` выбирает `k + 1`.
Добавляйте последний отсчёт задания для последнего измерения. Если управление
задано отклонением от балансировки, последовательно добавляйте и вычитайте
балансировочный угол на границе объекта и обратной связи.

## 4. Проверьте слежение, управление и идентификацию вместе


```python
# Select transitions by their start time.
transition_time = time[:-1]
for label, start, stop in [("Healthy", 40, 60), ("Faulty", 65, 80)]:
    selected = (transition_time >= start) & (transition_time < stop)
    error = states[1:][selected] - reference[0]
    print(label, "RMSE [rad/s]:", np.sqrt(np.mean(error**2)))

fig, axes = plt.subplots(3, 1, figsize=(11, 9), sharex=True,
                         constrained_layout=True)
axes[0].plot(time, states, label="Measured rate")
axes[0].axhline(reference[0], color="black", linestyle="--", label="Reference")
axes[0].set_ylabel("Rate [rad/s]")
axes[1].step(time[:-1], actions, where="post", label="Applied input")
axes[1].set_ylabel("Input")
axes[2].plot(time[1:], estimates, label="Identified discrete G")
axes[2].plot(time[1:], b * np.where(time[:-1] < 60, 1.0, 0.7),
             linestyle="--", label="True G (evaluation only)")
axes[2].set(ylabel="Discrete input gain", xlabel="Time [s]")
for ax in axes:
    ax.axvspan(0, 20, color="grey", alpha=0.12, label="Initial identification")
    ax.axvline(60, color="firebrick", linestyle=":", label="Plant change")
    ax.grid(alpha=0.25)
    ax.legend(loc="best")
plt.show()
```


![Слежение iADP по скорости, приложенное управление и оценённый коэффициент входа](../../assets/images/cookbook_06_iadp_learning.png)

На графике сверху — скорость и задание, в центре — приложенный вход, снизу —
оценённый и истинный дискретные коэффициенты. Первые 20 с выделены серым,
изменение объекта на 60 с — вертикальной линией. Начальное разомкнутое возбуждение
намеренно создаёт ошибку слежения. Измеряйте качество замкнутого управления после
этого этапа и сохраняйте полную траекторию, чтобы начальное поведение было видно.

| Окно проверки / величина | Контрольный результат |
|---|---:|
| RMSE исправного объекта, начала переходов в [40, 60) с | 2.762 × 10⁻⁵ рад/с |
| RMSE после отказа, начала переходов в [65, 80) с | 1.153 × 10⁻⁵ рад/с |
| Конечная оценка дискретного входного коэффициента | 0.000699300466138 |
| Истинный входной коэффициент после отказа | 0.000699300466433 |

Окна имеют разную предысторию адаптации; вторая RMSE также исключает первые 5 с
после изменения. Меньшая поздняя ошибка не означает, что отказ улучшил объект.
В [интерактивном ноутбуке](https://github.com/TensorAeroSpace/TensorAeroSpace/blob/develop/example/reinforcement_learning/incremental_adp/example_iadp_paper.ipynb) приведён тот же прямой
цикл SDK с выполненными графиками и метриками. Измените возбуждение или веса
и выполните все ячейки заново для сравнения результатов.

## 5. Сохраните регулятор и проверьте продолжение

```python
run_dir = agent.save("./checkpoints/recipe06")
restored = IADPAgent.from_pretrained(run_dir)
np.testing.assert_array_equal(
    agent.predict(x, reference), restored.predict(x, reference),
)

```

Так проверяется следующая команда при одинаковом измерении. Для продолжения
всего эксперимента нужно также сохранить состояние объекта, время, задание,
состояния генераторов случайных чисел и приводов.

## Типичные проблемы

| Симптом | Что проверить |
|---|---|
| Нулевое управление при начальном `G = 0` | Задайте изменяющееся начальное возбуждение или обоснованную номинальную оценку. |
| Реакция в неправильную сторону | Знак входа, единицы, порядок состояний и соглашение о балансировке. |
| Рост нормы критика или вырожденное уравнение политики | Масштабы признаков, возбуждение, невязку модели и полную траекторию; число отсчётов само по себе не обеспечивает информативную оценку. |
| Хорошее слежение при дрейфе параметров | Неучтённую динамику и возбуждение; слежение не доказывает сходимость параметров. |
| AA-INDI не принимает наблюдение | Используйте `FlightMeasurement` с единицами и метками времени из рецепта 14. |

`pinv(0)` равна нулю, а не бесконечности. Почти вырожденная ненулевая эффективность
может давать большие запрошенные приращения, поэтому нужно контролировать
обусловленность и реальные ограничения приводов. Настройки адаптации сами по себе
не доказывают устойчивость самолёта: проверяйте физику и качество управления
в каждом целевом сценарии.
